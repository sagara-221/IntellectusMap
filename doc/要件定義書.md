# 理解の地図（Knowledge Gap Mapper）要件定義書

## 1. プロジェクト概要

### 1.1 背景・課題分析

#### 1.1.1 独学・自律学習における「理解の空白（Knowledge Gap）」問題
情報技術や専門知識の独学において、学習者が直面する最大の障壁は「自分が何を理解していて、何が分かっていないのか（無知の無知）を客観視できない」点にある。
従来の学習ツールや問題集では、単一問題の正誤判定にとどまり、前提概念の抜け漏れや派生分野への体系的な繋がりを把握できない。

#### 1.1.2 既存学習プロセスの課題
1. **知識の階層構造の欠落**: 用語の暗記に終始し、親概念・子概念・依存関係の全体像が見えない。
2. **画一的な出題フロー**: 学習者の理解水準に関係なく固定的な問題が出題され、既知事項の反復や難解すぎる問題による挫折が生じる。
3. **学習範囲の閉塞性**: 1つのテーマを学んだ後、関連するどの分野へ学習を広げるべきか（発散・派生）の指針がない。
4. **学習履歴・理解度の不可視性**: 過去の回答や自己認識と客観的テスト結果の乖離を可視化・追跡する仕組みがない。

### 1.2 目的とビジョン

本システム「理解の地図（Knowledge Gap Mapper）」は、LLMを活用して任意の学習テーマを知識木構造（ノード・エッジ）へ動的に分解し、4択適応型診断テストおよび発散的学習を通じて、学習者の知識ギャップを明視化・解消する自律学習支援プラットフォームである。

## 2. ユーザーペルソナとユースケース

### 2.1 対象ユーザーペルソナ
- **自律型エンジニア・学習者**: 新しい技術スタックや概念を体系的に素早くキャッチアップしたい学習者。
- **資格・試験受験者**: 自身の弱点分野をピンポイントで特定し、効率的に克服したい受験者。
- **リスキリング人材**: 広範な前提知識が必要な先端分野（AI、クラウド、分散システム等）へ参入する学習者。

### 2.2 主要ユースケース

#### UC-01: テーマ入力と知識構造の自動生成
- 学習者が関心のあるテーマ（例: 「Reactの状態管理」「OAuth 2.0」「Kubernetesアーキテクチャ」）を入力。
- LLMが主要概念・サブ概念・前提依存関係を抽出し、知識ツリー（マインドマップ状）として即座に描画。

#### UC-02: 4択適応型診断テストによる客観的理解度判定
- 各ノードについて、概念定義・メカニズム・応用に関する4択問題を動的生成。
- ユーザーの選択回答を即時採点し、正解・不正解・知識ギャップを特定して理解度レベル（High / Medium / Low / 未判定）を自動更新。

#### UC-03: 弱点ノードの深掘り・段階的分解
- 不正解（Low）や部分理解（Medium）となったノードをさらに詳細な子概念へ手動分解・自動分岐して克服。

#### UC-04: 発散的テーマ探究と派生マップ作成
- 学習済みのノードから、発展的な応用テーマや関連技術への「発散（Divergence）候補」を提案。
- 派生した新テーマを選択することで、親マップと紐付いた新規マップを連続生成（系統樹・ツリー管理）。

#### UC-05: 知識ノード横断検索と弱点克服
- 複数の学習マップに跨るノード群を横断検索・フィルタリングし、未習得ノードを集中確認・復習。

#### UC-06: 自由対話による理解度診断（チャット診断）
- 選択肢クイズに加え、学習者が自然言語の自由文で質問や自身の理解内容をAIへ送信。
- AIの思考・回答をリアルタイムストリーミング（SSE）で受信しながら対話。
- AIが発言内容から理解度エビデンスをバックグラウンドで自動抽出し、知識ツリー上のノード理解度や関連概念の展開を動的に更新。

## 3. 機能要件

### 3.1 診断・探索機能
| 機能ID | 機能名 | 要件概要 |
| --- | --- | --- |
| F-01 | テーマ分解・マップ生成 | ユーザー入力テーマを起点に階層的知識ノード群と依存関係をLLM自動生成 |
| F-02 | 4択診断問題動的生成 | 対象ノードの概念定義・メカニズム・応用に関する4択適応型問題を自動生成 |
| F-03 | 4択回答評価・理解度判定 | 選択回答を自動判定し、正誤・解説・不足知識・理解度ランクを即時判定 |
| F-04 | 弱点手動分解 | 弱点ノードを詳細な子概念に再分解し、より基礎的な階層を展開 |
| F-05 | 診断ポリシー制御 | 理解度に応じた次問遷移、下位概念への自動掘り下げ（Decompose）を制御 |
| F-06 | 概念手動追加 | 知識マップへのノード手動追加 |
| F-07 | 概念手動分解 | 特定ノードの更なる細分化（子ノード生成）を手動指示 |
| F-08 | 自由文対話ストリーミング | 自然言語発言の送信とSSEリアルタイムストリーミングによるAI解説応答 |
| F-09 | 対話エビデンス自動抽出・ノード反映 | 会話ログから理解度根拠（実体験・言及・自己申告）を自動抽出しツリーへ反映 |
| F-19 | 会話スレッド管理・エビデンス再評価 | 話題ごとの会話セッション切り替え、ノード追加時の過去ログ再評価（Reprocess） |

### 3.2 マップ・系統管理機能
| 機能ID | 機能名 | 要件概要 |
| --- | --- | --- |
| F-10 | マップ一覧・詳細管理 | 作成したマップの一覧表示、タイトル・スコープ編集、削除 |
| F-11 | 発散候補提案・マップ派生 | 選択概念を起点とした発展テーマ候補生成および派生マップ作成 |
| F-12 | 系統樹可視化 | 親マップから派生マップへの分岐履歴（Lineage）をグラフ表示 |
| F-13 | 回答履歴閲覧 | 過去に出題された全問題・回答・評価フィードバックの時系列表示 |

### 3.3 分析・横断検索機能
| 機能ID | 機能名 | 要件概要 |
| --- | --- | --- |
| F-14 | 全体・系統別理解度集計 | 全マップ、特定系統、個別マップごとの理解度分布（High/Med/Low）集計 |
| F-15 | 知識ノード横断検索 | 全マップに含まれる概念ノードのキーワード検索、理解度絞り込み、ソート |

### 3.4 認証・認可機能
| 機能ID | 機能名 | 要件概要 |
| --- | --- | --- |
| F-16 | Google OAuth認証 | Googleアカウントを利用したセキュアなサインイン・セッショントークン検証 |
| F-17 | ゲスト利用フォールバック | 未認証時でもセッション・マップ探索が可能なゲストモード提供 |
| F-18 | データアクセス認可制御 | ログインユーザーごとのセッション・マップデータの分離保護 |

## 4. 非機能要件

### 4.1 ユーザビリティ・UI/UX
- **直感的なグラフ操作**: マインドマップ状のノードクリックで診断・詳細確認・分解が即座に実行可能であること。
- **レスポンシブデザイン**: PCブラウザを中心に、タブレット等の画面幅にも最適化。
- **ダークテーマ/モダンデザイン**: 洗練された配色、視認性の高いステータスカラー（High: 緑, Medium: 黄, Low: 赤, Unknown: 灰）。

### 4.2 性能・可用性
- **LLM呼び出し最適化**:
  - 問題生成・分解のキャッシュ機構（事前分解キャッシュ、Embeddings）。
  - バッチ処理による一括問題生成での低レイテンシ化。
- **レスポンス時間目標**:
  - 通常API（一覧・取得）: 200ms以内。
  - LLM推論を伴う処理（分解・生成・評価）: 3〜5秒以内。
- **可用性**: Cloud Runによる自動スケーリング構成。

### 4.3 拡張性・データベース設計
- **クラウドデータベース構成**:
  - 本番運用環境: Google Cloud Firestore（サーバーレスNoSQL Native Mode）。
- **マルチエージェント基盤**:
  - Google Cloud Vertex AI / Agent Development Kit (ADK) によるマルチエージェント協調動作。

### 4.4 セキュリティ
- Google IDトークン検証（本番運用時）。
- HTTPS（TLS）による通信経路暗号化。
- Firestoreセキュリティルールおよびサーバーサイドでのテナント分離。

---

## 5. 制約事項・前提条件
- LLMバックエンドは Google Gemini（gemini-3.5-flash-lite）および Google ADK / Vertex AI を採用。
- ブラウザ環境は最新版 Google Chrome, Safari, Edge をサポート。
