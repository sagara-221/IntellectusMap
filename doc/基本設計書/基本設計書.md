# 理解の地図（Knowledge Gap Mapper）基本設計書

## 1. システム概要

### 1.1 システム目的

本システムは、学習者が任意のトピックについて自身の「知識の抜け漏れ（Knowledge Gap）」を特定・解消するための自律型診断・探索プラットフォームである。
最新の超低レイテンシ基盤モデル（Gemini 3.5 Flash-Lite）およびエージェント基盤（Agent Development Kit: ADK）を用いて概念の木構造分解、4択適応型テスト出題、回答採点・解説生成、および関連分野への発散的展開を提供する。

### 1.2 システム構成概要

**本番技術スタック (Google Cloud Platform)**:
- **フロントエンド**: React 18, TypeScript, Vite, Vanilla CSS (Firebase Hosting 配信)
- **バックエンド**: Cloud Run (FastAPI, Python 3.12, Uvicorn)
- **AI / マルチエージェント基盤**: Google Cloud Vertex AI / Agent Development Kit (ADK) (Gemini 3.5 Flash-Lite)
- **埋め込みモデル**: Vertex AI Embeddings (`gemini-embedding-001`)
- **データベース**: Google Cloud Firestore (Native NoSQL Mode)
- **認証・認可**: Google Identity Services (GIS / OAuth 2.0 / OIDC JWT)

| **クライアント** | Webブラウザ (React SPA) | Google GIS ログインUI、知識ツリー可視化（SSE連動エージェント稼働ノードリアルタイム描画）、4択診断UI、正誤解説表示 |

| **バックエンド API** | Cloud Run (FastAPI) | GIS OIDC JWT検証、`user_id` 別データ完全分離、ADK Runner 制御、SSE進捗イベント配信（実行ノードID/名称連携）、状態遷移管理 |
| **知識分解エージェント** | ADK / Vertex AI (Gemini 3.5 Flash-Lite) | 観点計画策定、子概念ツリー自動生成、次層先読み |
| **出題エージェント** | ADK / Vertex AI (Gemini 3.5 Flash-Lite) | 未評価Targetに対する4択問題生成、4択選択肢・解説作成 |
| **採点エージェント** | ADK / Vertex AI (Gemini 3.5 Flash-Lite) | 4択選択肢の正誤判定、実証知識・不足知識・知識ギャップの特定、解説生成 |
| **会話診断・エビデンス抽出サービス** | FastAPI / `ChatService` (Gemini 3.5 Flash-Lite) | 自由対話のSSEストリーミング応答、会話からの理解エビデンス（実体験・言及・自己申告）バックグラウンド自動抽出、ツリー理解度反映 |
| **概念統合エージェント** | ADK / Vertex AI (Gemini 3.5 Flash-Lite) | `gemini-embedding-001` による類似度判定、標準概念ノード作成・グラフ統合マージ |
| **データベース** | Cloud Firestore | `sessions`（ツリー・状態・会話State集約Doc）、`lineages`、`relations`、`divergence_candidates` 永続化 |

## 3. データフロー設計

### 3.1 診断セッション開始・知識分解フロー
```mermaid
sequenceDiagram
  autonumber
  actor User as 学習者
  participant Frontend as React SPA
  participant Backend as Cloud Run (FastAPI)
  participant ADK as Google ADK / Vertex AI (Gemini 3.5 Flash-Lite)
  participant Firestore as Cloud Firestore

  User->>Frontend: 学習テーマ入力（例: OAuth 2.0）
  Frontend->>Backend: POST /api/sessions (topic, goal, level) [Bearer JWT]
  Backend->>Backend: Google OIDC JWT検証・user_id抽出
  Backend-->>Frontend: SSE接続確立 (agent_progress ストリーム)
  Backend->>ADK: 知識分解エージェント起動 (Decompose)
  Backend-->>Frontend: SSE: 知識分解中 (RootノードID・名称)
  Frontend-->>User: Rootノード上で分解エージェント光彩・バッジ描画
  ADK-->>Backend: 概念木構造 JSON (Root + Sub-concepts + Edges)
  Backend->>ADK: 出題エージェント起動 (Generate Question)
  Backend-->>Frontend: SSE: 出題作成中 (TargetノードID・名称)
  Frontend-->>User: 対象ノード上で出題エージェント稼働表示
  ADK-->>Backend: 診断問題 JSON (Question, Options, Rubric)
  Backend->>Firestore: sessions/{id} ドキュメント永続化
  Backend-->>Frontend: 診断開始レスポンス (Tree + First Question)
  Frontend-->>User: 知識マップ描画 & 初問表示
```

### 3.2 回答提出・評価・適応型分岐フロー
```mermaid
sequenceDiagram
  autonumber
  actor User as 学習者
  participant Frontend as React SPA
  participant Backend as Cloud Run (FastAPI)
  participant ADK as Google ADK / Vertex AI (Gemini 3.5 Flash-Lite)
  participant Firestore as Cloud Firestore

  User->>Frontend: 回答選択・送信
  Frontend->>Backend: POST /api/sessions/{id}/answers [Bearer JWT]
  Backend-->>Frontend: SSE: 採点中 (回答ノードID・名称)
  Frontend-->>User: 回答ノード上で採点エージェント光彩・バッジ描画
  Backend->>ADK: 採点エージェント起動 (Evaluate Answer)
  ADK-->>Backend: 評価結果 JSON (Score, Level, Explanation, Gap)
  Backend->>Backend: 診断ポリシー判定 (Decompose / Next Concept)
  opt 弱点掘り下げが必要な場合
      Backend-->>Frontend: SSE: 追加分解中 (該当ノードID・名称)
      Backend->>ADK: 知識分解エージェント起動 (Sub-decompose)
      ADK-->>Backend: 追加子ノード群
  end
  Backend-->>Frontend: SSE: 次問生成中 (次ノードID・名称)
  Backend->>ADK: 出題エージェント起動 (Next Question)
  ADK-->>Backend: 新規問題 JSON
  Backend->>Firestore: sessions/{id} 状態・回答履歴更新
  Backend-->>Frontend: 採点結果・更新後マップ・次問返却
  Frontend-->>User: 正誤解説表示・マップ色更新 (緑/黄/赤)
```

### 3.3 会話診断・エビデンス自動抽出フロー
```mermaid
sequenceDiagram
  autonumber
  actor User as 学習者
  participant Frontend as React SPA / クライアント
  participant Backend as Cloud Run (FastAPI / ChatService)
  participant LLM as Vertex AI (Gemini 3.5 Flash-Lite)
  participant Firestore as Cloud Firestore

  User->>Backend: POST /api/sessions/{id}/chat (自由発言テキスト)
  Backend-->>User: SSE接続確立 (トークンストリーミング)
  par フォアグラウンド対話ストリーミング
      loop トークン順次生成
          LLM-->>Backend: 回答テキスト差分
          Backend-->>User: event: delta (text)
      end
      Backend-->>User: event: complete (session)
  and バックグラウンドエビデンス抽出・更新
      Backend->>LLM: 発言から経験単位 (ExperienceUnit) 抽出
      LLM-->>Backend: 抽出された根拠・言及・自己申告リスト
      Backend->>Backend: 知識ツリーノードとの照合・評価スコア算出
      Backend->>Firestore: sessions/{id} (chat.observations, 理解度) 保存
  end
```

## 5. 認可・データ分離設計

### 5.1 Google IDトークン検証
- すべての保護対象APIリクエストについて、HTTPヘッダー `Authorization: Bearer <ID_TOKEN>` を受信。
- Google公開鍵証明書を用いてトークンの完全性・有効期限・Audienceを検証し、`user_id`（Google sub値）を確定。

### 5.2 Firestoreにおけるマルチテナント分離
- リポジトリ層において全クエリに `user_id == current_user` 条件を強制適用。
- 他ユーザーのセッション・マップ・系統への読み書きをサーバーサイドで完全に遮断。
