# 04. 診断ポリシー・分岐判定 機能設計書

## 1. 機能概要

- 学習者の回答結果および理解度ステータスに基づき、次にとるべきアクション（同階層の別概念へ進むか、下位概念へ掘り下げて細分化するか、前提概念へ戻るか）を自律判定する。
- 不要な重複診断を防ぎつつ、理解不足（Low判定）が発生した箇所を重点的に補強する適応型（Adaptive）学習フローを実現する。

## 2. 入出力

### 入力
- セッション状態 (`Session`)
- 直前の採点結果 (`EvaluationResult`: 理解度 `understanding`, スコア `score`)
- 現在ノード情報 (`ConceptNode`: 階層深さ `depth`, 子ノード有無)
- ポリシー設定 (`DiagnosticPolicy`: 最大深さ `max_depth`, 自動分解閾値等)

### 出力
- ポリシー判定結果 (`PolicyDecision`):
  - 次のアクション種別 (`action_type`: `advance_sibling` / `decompose_current` / `fallback_prerequisite` / `complete_diagnostic`)
  - 次に出題すべき対象概念ID (`next_concept_id`)
  - 理由・判断根拠 (`reason`)

## 3. 処理フロー

```mermaid
flowchart TD
    Start([回答評価完了]) --> CheckScore{理解度判定}
    
    CheckScore -->|High (定着)| HasSiblings{未診断の兄弟/上位ノードがあるか？}
    HasSiblings -->|Yes| NextSibling[次の未診断ノードへ進む]
    HasSiblings -->|No| CheckAllDone{ツリー全ノード診断済？}
    
    CheckScore -->|Medium (概ね理解)| AskDecompose{掘り下げ希望 or 境界条件？}
    AskDecompose -->|Yes| DecomposeNode[概念分解を実行し子ノード出題]
    AskDecompose -->|No| NextSibling
    
    CheckScore -->|Low (理解不足)| CheckDepth{現在深さ < max_depth ?}
    CheckDepth -->|Yes| AutoDecompose[自動分解: 基礎サブ概念へ掘り下げ]
    CheckDepth -->|No| CheckPrereq{前提ノードが存在するか？}
    CheckPrereq -->|Yes| Fallback[前提概念ノードの出題へ遷移]
    CheckPrereq -->|No| NextSibling
    
    CheckAllDone -->|Yes| Finish([診断セッション完了])
    CheckAllDone -->|No| NextSibling
```

1. **スコア評価に基づく分岐**:
   - `high`: 当該概念は習得済みとみなし、ツリー内の次の未診断ノード（BFS順または依存順）を選択。
   - `low`: 知識のギャップが発生。現在ノードの深さが最大深さ（デフォルト3）未満であれば、自動的に下位概念へ分解（`decompose`）を指示。
2. **依存関係（Prerequisite）のチェック**:
   - 概念Aを学ぶ前提となる概念Bが `low` または未受検の場合、優先度を再調整。
3. **終了判定**:
   - ツリー内の全ノードが診断済み（`high` または `medium`）となった場合、セッション完了フラグを設定。

## 4. バリデーション

- 無限ループ防止のため、同一ノードへの連続分解回数は最大2回までとする。
- ツリーの最大深さは3階層までに制限。

## 5. エラーハンドリング

| エラーケース | 対処方針 | 備考 |
| --- | --- | --- |
| 次の候補ノードが見つからない | 未診断ノードを探索し、存在しない場合は診断完了とする | 正常系フォールバック |
| ポリシー設定値不正 | デフォルトポリシー（深さ3、BFS探索）を強制適用 | 設定防御 |
