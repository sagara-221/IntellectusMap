# 07. マップ管理 機能設計書

## 1. 機能概要

- ユーザーが作成した知識マップの一覧表示、個別マップの詳細ツリー取得、メタデータ（タイトル・スコープ）の更新、およびマップ削除を提供する。
- 派生マップ削除時は関連リレーション・候補データを整理し、ルートマップ削除時は系統樹の整合性を維持した上でカスケード削除を実行する。
- 永続化層は Firestore（`sessions`, `knowledge_maps`, `map_lineages` コレクション）およびインメモリリポジトリで管理される。

## 2. 入出力

### 入力
- マップ一覧取得: なし (認証情報より `user_id` 解決)
- マップ詳細取得: マップID (`map_id`)
- マップ更新: マップID (`map_id`), 更新タイトル (`title`), 更新スコープ (`scope`)
- マップ削除: マップID (`map_id`)

### 出力
- マップ一覧 (`List[MapSummary]`: map_id, lineage_id, title, scope, concept_count, stats, updated_at)
- マップ詳細 (`MapDetail`: 完全ツリー、ノード情報、エッジ情報、理解度サマリ)
- 更新・削除完了メッセージ

## 3. 処理フロー

### 3.1 マップ一覧取得フロー
1. Firestore の `knowledge_maps` からユーザー所有レコードを照会。
2. 各マップのセッションツリーを走査し、ノード総数、診断済みノード数、弱点ノード数などの統計情報（`stats`）を集計。
3. 派生関係（親マップ名、起点概念名）を付与して返却。

### 3.2 マップ削除フロー
1. 対象マップの存在およびアクセス権限（所有者）を確認。
2. 親子マップ関係（`knowledge_map_relations`）から当該マップが関与するリレーションを削除。
3. 関連する発散候補（`divergence_candidates`）を削除。
4. 本体セッションレコード（`sessions`）および `knowledge_maps` を削除。
5. 当該マップが系統のルートマップであり、他に派生マップが存在しない場合は `map_lineages` もクリーンアップ。

## 4. バリデーション

- `title`: 1文字以上255文字以下（更新時）。
- 存在しない `map_id` へのアクセスは 404 Not Found。
- 他人のマップに対する更新・削除要求は 403 Forbidden。

## 5. エラーハンドリング

| エラーケース | ステータスコード | レスポンス例 | 備考 |
| --- | --- | --- | --- |
| マップが存在しない | 404 | `{"detail": "指定されたマップが見つかりません。"}` | ID不在 |
| 権限不足 | 403 | `{"detail": "このマップに対する操作権限がありません。"}` | 認可エラー |
